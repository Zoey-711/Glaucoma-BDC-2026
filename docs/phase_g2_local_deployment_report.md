# Phase G2：F01 / F04 RTX 4060 部署对照

日期：2026-10-30。基础代码版本：Phase G commit `07fcc3f`。仅做冻结候选推理与测速；未训练、未读取 Test、未生成比赛提交。GPU 为本机 **NVIDIA GeForce RTX 4060 Laptop GPU**，驱动 581.08；Windows 10、Python 3.11.9、PyTorch 2.10.0+cu128、torchvision 0.25.0+cu128、CUDA 12.8。结果是本地工程实测，不能作为 T4 成绩。

## 固定推理定义

- **F01**：G01 + B02，FP32，两模型输出 logit 各自 sigmoid 后等权平均，阈值 0.5。
- **F04**：G01 + G02，FP32，同样按各自概率等权平均，阈值 0.5。
- TTA 均为 identity。模型、配置与成员哈希保存在 `outputs/phase_g2/candidates/`；逐轮 CSV、每图时间和 GPU 记录在同一目录的 Phase G2 输出中。
- 两模型共用同一张解码后的 RGB 图像。G01/B02 仍用各自原配置的 224 输入，G02 仍用其 384 输入和 checkpoint 内预处理。计时包含一次磁盘读取与解码；解码时间各分一半计入 F01/F04 单图时间。每个模型自己的输入预处理、前向、概率融合/输出、CSV 写入和 flush 均计时，并在 CUDA 前后同步。
- 每个模型恰有 5 张预热图、100 张计时图、batch=1、3 轮。轮次顺序为 F01→F04、F04→F01、F01→F04，即 ABBA 后再 AB；每轮内部两模型对每张图共享一次读取和解码。

## 4060 测速

| 候选 | 平均延迟 | P95 | 三轮均值（ms/图） | 加载文件合计 | 峰值显存* | 4060 平均是否低于 100 ms |
|---|---:|---:|---|---:|---:|---|
| F01 | **89.89 ms** | 155.16 ms | 91.99 / 88.49 / 89.19 | **127,626,524 B**（127.63 MB） | 431.59 MB | 是 |
| F04 | **120.93 ms** | 212.83 ms | 122.43 / 119.70 / 120.66 | **222,660,887 B**（222.66 MB） | 431.59 MB | 否 |

F04 比 F01 慢 **31.03 ms/图，34.52%**。两套加载文件合计均低于 500,000,000 B。峰值显存是两个候选同时加载时 PyTorch 进程的峰值 allocated；峰值 reserved 为 471.86 MB。测速期间 `nvidia-smi` 设备显存约 1.85–1.91 GB（含桌面及其他设备占用），温度约 53–57°C。上述均值是单图平均限制的本地测量；P95 超过 100 ms，反映部分图像耗时会高于平均值。

## 冻结预测一致性

对官方完整 Val 的 5,849 张逐图使用同一 FP32 Predictor 与融合定义重新推理，并与冻结 CSV 比较：

| 候选 | 最大概率绝对差 | 平均绝对差 | 差值 >0.001 的样本 | Pred_Label 变化 |
|---|---:|---:|---:|---:|
| F01 | 0.0007429421 | 0.0000125625 | 0 | 0 |
| F04 | 0.0000159293 | 0.0000001283 | 0 | 0 |

差异均处于 0.001 容差内且没有阈值分类变化。F01 的 100 张计时子集中，三轮均出现 1 个正负样本对的细微排序互换（最大概率差约 0.000299）；F04 子集的排序没有变化。完整 Val 全量报告统计概率与标签差异，不将这种浮点实现差异称为逐 bit 相同。

`predict.py`、`cost.py` 和本次交错测速共用 `Predictor.predict_one` / `predict_decoded_one` 推理写出路径；两者未切换 FP16。没有执行 FP16。

## 结论

F04 仍是当前 Val AUROC 最高的融合候选，继续保留。它在本地 RTX 4060 上平均 **120.93 ms**，超过 100 ms；F01 平均 **89.89 ms**，低于 100 ms，但 P95 为 155.16 ms。模型体积方面两者均满足 500 MB。

**T4 状态仍为 UNVERIFIED。** RTX 4060 Laptop 的计算能力、热/功耗约束、CPU 图像解码速度和竞赛运行环境均不同；本次结果不能推断 T4 是否通过。F04 两个 ConvNeXt 成员、其中一个为 384 输入，部署延迟风险较高，但需要在官方 T4 环境按规定 5 张预热、100 张 batch=1、连续 3 轮测量才能定论。不得因 4060 超时淘汰 F04，也不得将 4060 达标写成 T4 通过。

复现准备：先用 `python -m scripts.phase_g2 --prepare` 建立从冻结模型复制的候选（只运行一次），再运行 `python -m scripts.phase_g2 --benchmark` 做交错抽样，或 `python -m scripts.phase_g2 --full-val` 做全 Val 一致性复核。完整实测证据在本机受 `.gitignore` 保护的 `outputs/phase_g2/`，不含在代码提交中。
